## What it argues
A designer argues that the chat box is a poor interface for large language models, in five headed claims.

1. "Text inputs have no affordances." The user meets "a blank face" and "endlessly confident" output, and "the burden to learn what works still lies with every single user. When it could instead be baked into the interface" (section "Text inputs have no affordances").
2. "Prompts are just a pile of context." Everything in a prompt is context the interface could collect with controls. She shows a writing tool with fields for type of writing, audience and feel, and a documentation assistant (Copilot for Docs) with sliders, because "A new developer doesn't want the same responses as an experienced one."
3. "Responses are isolated." Two successive rewrites of a paragraph from *Walden* leave the user "scroll[ing] back and forth between responses, reading them line by line"; she calls the lack of a "working buffer" "a complete non-starter."
4. The implementation–evaluation loop. A chat forces the user to switch between asking and reading, so "There is no 'flow' state if I'm stopping every few seconds to read a response."
5. "Avoid No man's land." On a scale from human task (0%) to tool (50%) to machine (100%), a half-automated task leaves "a No man's land where the human is still required to make decisions, but they're not in control of the outcome." She wants "more tools and fewer operated machines."

There are no data. The examples are her own prototypes and one prompt from a public list.
